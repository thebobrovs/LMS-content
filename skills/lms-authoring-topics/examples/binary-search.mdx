## The idea

**Binary search** finds a target in a **sorted** array by comparing it to the
middle element and discarding the half that can't contain it. Each comparison
halves the search range, so even a million-element array takes at most ~20 steps.

Reading `arr[mid]` is O(1) (see [arrays](/topics/fundamentals/arrays)), and we do
it `log₂(n)` times — that's the whole cost.

<Callout type="note">
Binary search only works on **sorted** data. On unsorted data you'd pay O(n log n)
to sort first — only worth it if you search the same array many times.
</Callout>
