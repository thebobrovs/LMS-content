# 2.3 · Feeding the beast — data pipelines & checkpointing

**Slug:** `ml-systems/data-pipeline-io` · **Level:** 200 · **Difficulty:** intermediate · **~13 min**
**Prerequisites:** [] · **relatedTo:** `spmd-multi-host`, `tpu-provisioning-vm`

## TLDR — why / what / how

**Why.** The most expensive failure mode in TPU training isn't a crash — it's
**idle silicon**. If the host CPUs can't decode/augment/feed batches as fast as the
chips consume them, a million-dollar slice waits on a `for` loop. And when hardware
*does* fail mid-run, your only insurance is the checkpoint cadence. This topic is
both halves of I/O: **feeding** and **saving**.

**What.** The infeed-bound pathology (step time = max(compute, input)); **Grain** —
the JAX-stack loader: deterministic, *checkpointable* input state, prefetch to
overlap host work with device compute; **Orbax** — async checkpointing (HBM → GCS
without stalling steps), **emergency checkpointing** (SIGTERM autosave on
preemption — ties to Spot/DWS from 1.8), and atomically checkpointing **data
state + model state together** so a resumed run is bit-identical.

**How.** Sim: **infeed throughput** — two conveyor lanes (host prep vs device
compute); drag host-side cost and prefetch depth, watch the TPU's idle gaps and
the MFU readout; the fix (prefetch/parallel workers) closes the gap. Lab: codelab
notebook — measure a starved loop vs a prefetched Grain pipeline (CPU-first).

## Accuracy gates (verified 2026-06)

- **Grain** is the JAX-stack input library: deterministic global shuffle,
  **checkpointable DataLoader state** — the "resume mid-epoch, bit-identical"
  claim is real. [docs.cloud.google.com/tpu/docs/jax-ai-stack, google-grain docs]
- **Orbax**: async distributed checkpointing; **emergency checkpointing**
  (AsyncCheckpointer saves on SIGTERM); multi-tier/"hero-scale" resilience; also
  faster workload *start* (restore). Confirm current class names at draft time.
- Atomic Grain+Orbax state (data iterator + model in one checkpoint) is the
  documented reproducibility pattern. ✓
- tf.data still exists/interops, but Grain is the recommendation for JAX on TPU —
  frame tf.data as "you'll see it in older pipelines."

## Learning objectives

1. Diagnose infeed-bound training: step time = max(host_input, device_compute);
   idle TPU = the symptom, host pipeline = the cause.
2. Name Grain's two superpowers: determinism (global shuffle, seeded) and
   checkpointable input state.
3. Explain async checkpointing: snapshot to host memory, upload to GCS in the
   background, training never stops — and why checkpoint traffic rides the DCN.
4. Connect emergency checkpointing to capacity modes: SIGTERM autosave is what
   makes Spot/Flex-start survivable (1.8 callback — "Spot needs checkpoints").

## Must-learn spine

- The idle-TPU pathology and how to spot it (step-time gap; the sim makes it visceral).
- Prefetch & parallel workers: overlap host prep with device compute; the fix is
  pipeline-shaped, not "more TPUs."
- Grain: deterministic, checkpointable, JAX-native (tf.data = legacy encounter).
- Orbax: async (don't stall steps), emergency (SIGTERM), and *with* Grain state for
  exact resume. Checkpoints ride the DCN to GCS (1.6/1.8 storage callback).

## Sim spec — `infeed-throughput`

Two-lane pipeline animation: HOST lane (decode→augment→batch) and TPU lane (steps).
Sliders: host ms/batch, prefetch depth, workers. Readouts: step time, TPU idle %,
effective MFU. The "aha": TPU idle gaps vanish when prefetch ≥ host/compute ratio.
Checkpoint `observe-infeed` when the learner first closes the gap.

## Quiz / flashcards (≈4 each)

- Step time = max(input, compute) — what "infeed-bound" means.
- Grain's determinism + checkpointable input state (why resume is bit-identical).
- Async vs synchronous checkpointing (what stalls, what doesn't).
- Why Spot/Flex-start capacity *requires* emergency checkpointing.
