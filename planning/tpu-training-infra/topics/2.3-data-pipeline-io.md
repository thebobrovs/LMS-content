## TLDR — why / what / how

**Why.** The most expensive failure mode in TPU training isn't a crash — it's **idle
silicon**. If the host CPUs can't decode/augment/batch data as fast as the chips consume it,
a million-dollar slice waits on a `for` loop. And when hardware *does* fail mid-run (it will,
at scale), your only insurance is checkpoint cadence. 2.3 is both halves of I/O: **feeding**
and **saving** — and both are pure infrastructure problems.

**What.** The infeed-bound pathology (`step time = max(host_input, device_compute)`); the fix
is pipeline-shaped — **prefetch + parallel workers** overlap host prep with device compute, not
"more TPUs". **Grain** — the JAX-stack loader: deterministic global shuffle + **checkpointable
iterator state**, so you resume mid-epoch bit-identically. **Orbax** — **async** checkpointing
(snapshot, then flush to GCS in the background so steps never stall), **Autocheckpoint** (saves
on an impending maintenance event / SIGTERM — what makes Spot/Flex-start survivable, the 1.8
callback), and checkpointing **data state + model state together** for an exact resume.

**How.** Sim: **input-pipeline-explorer** — two lanes (host prep vs device compute); drag host
cost / prefetch depth / workers and watch the TPU's idle gaps and the utilization (MFU) readout;
the gap closes when prefetch ≥ the host/compute ratio. Notebook: CPU-first — time a starved naive
loop vs a prefetched Grain pipeline, then checkpoint a Grain iterator with Orbax and resume
bit-identically.

## Accuracy gates (verified 2026-06; re-confirm fast-moving Grain/Orbax class names at draft)

- **Grain is the JAX-stack input library.** A `DataLoader` wires a **DataSource** + a **Sampler**
  + **transforms**, launches parallel worker processes, and yields a **stateful, checkpointable
  iterator**; data lives in **ArrayRecord** files. Determinism = stable global shuffle +
  checkpointable iterator. The "resume mid-epoch, bit-identical" claim is real and is the headline.
  [google-grain.readthedocs.io, developers.googleblog Grain+ArrayRecord, docs.cloud.google.com/tpu/docs/jax-ai-stack]
- **tf.data still interops** and you'll meet it in older pipelines — frame it as "legacy you'll
  read," Grain as the recommendation for JAX on TPU. (Don't teach tf.data as the default.)
- **Orbax** = `CheckpointManager` (save cadence via `save_interval_steps`, retention/cleanup);
  **async is ON by default** (background flush; turning it off tanks save perf). **Autocheckpoint**
  (Cloud TPU's name): `save()` detects an impending maintenance event and checkpoints even
  off-cadence — the SIGTERM/preemption autosave. Confirm exact class names (`CheckpointManager`,
  `AsyncCheckpointer`, `AsyncOptions`) at draft. [orbax.readthedocs.io, docs.cloud.google.com/tpu/docs/autocheckpoint, Orbax arxiv 2026]
- **Atomic model+data checkpoint:** Orbax checkpoints the Flax model state *and* the Grain
  `DatasetIterator` together in one consistent snapshot — the documented reproducibility pattern. ✓
- **Where the bytes go:** checkpoints flush to **GCS over the DCN** (1.6/1.8 storage callback),
  not ICI. Input data is read from attached storage (Hyperdisk ML / GCS) by the host.

## Must-learn spine (with the SRE bridge baked into each beat)

1. **Idle silicon is the enemy.** `step = max(host_input, device_compute)`. If host prep is slower,
   the chips stall and you pay for idle time. *SRE bridge:* textbook **producer/consumer
   backpressure** — the consumer (TPU) starves when the producer (host pipeline) can't keep up;
   idle TPU% is your "consumer starved" metric.
2. **The fix is pipeline-shaped, not more hardware.** **Prefetch** (a buffered queue of ready
   batches) + **parallel workers** (a worker pool decoding ahead) overlap host prep with device
   compute. *SRE bridge:* a bounded queue + a thread/worker pool in front of a hot consumer — you
   don't buy a faster consumer, you keep its inbox full. Prefetch depth ≈ how far ahead you buffer.
3. **Grain: deterministic + checkpointable.** Seeded global shuffle → reproducible; the iterator's
   position is **saved state**. *SRE bridge:* the data cursor is a **consumer offset** (like Kafka)
   — checkpoint the offset with the model and you resume exactly where you left off, no
   double-counting, no skipped data.
4. **Orbax async checkpointing.** Snapshot to host memory fast, **flush to GCS in the background**;
   the training loop never blocks on the write. *SRE bridge:* **write-behind / async WAL flush** —
   you don't block the hot path on durable storage; the flush rides the **DCN** to the object
   store, not the ICI.
5. **Autocheckpoint = a graceful-shutdown hook.** On an impending maintenance event / SIGTERM,
   Orbax saves even off-cadence. *SRE bridge:* a **preStop hook / SIGTERM handler** — it's what
   makes **preemptible/Spot** capacity safe to use, turning 1.8's "Spot is cheap but it gets
   reclaimed" into "Spot is cheap and we lose ≤ one checkpoint interval."

## Sim spec — `input-pipeline-explorer`

**Concept (one):** when host prep is slower than device compute, the TPU idles — and **prefetch
closes the gap** without touching the chips. **Standard:** Hyperstack tokens + light/dark via
`data-theme`, deterministic core, `prefers-reduced-motion` honored, real `createSim` SDK
(classic `<script src="./sim-sdk.js">`), one `sim.checkpoint("observe-infeed")`, `sim.resize` in
rAF. No game/score framing. (Follow the 2.1/2.2 builds for SDK wiring, theme, reduced-motion.)

**Layout.** Two horizontal lanes that advance in lockstep "steps":
- **HOST lane** — decode → augment → batch, taking `host_ms` per batch (slider).
- **TPU lane** — one training step, fixed `compute_ms` per step.
A **prefetch buffer** (depth slider, 0–N) sits between them; **parallel workers** (slider, 1–8)
divides effective `host_ms` by the worker count (with a "diminishing returns" note — host has
finite cores).

**Readouts (deterministic from the sliders).** Effective step time = `max(compute_ms,
host_ms/workers)` once prefetch ≥ ratio, else the larger gap; **TPU idle %**; **utilization (MFU
proxy) %** = `compute_ms / step_time`. The "aha": idle gaps vanish when prefetch depth ≥
`ceil(host_ms / (workers·compute_ms))`. Checkpoint fires the first time the learner drives idle% to ~0.

**Audience check.** Run the audience-reviewer on the labels — Sam should read it as a
producer/consumer queue and immediately know the lever is prefetch/workers, not more TPUs.
