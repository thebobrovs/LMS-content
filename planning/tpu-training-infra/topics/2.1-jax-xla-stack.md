# 2.1 · The JAX/XLA stack — no black boxes

**Slug:** `ml-systems/jax-xla-stack` · **Level:** 200 · **Difficulty:** intermediate · **~14 min**
**Prerequisites:** [] · **relatedTo:** `tpu-chip-systolic-array`, `gpu-or-tpu`

## TLDR — why / what / how

**Why.** L100 ended at "your code runs on the host and dispatches to the chip." L200
opens the box: *what actually happens* between `model.py` and the MXU. The thesis of
the level: **no black boxes** — if you can read what XLA did to your program, you can
debug OOMs before training starts and explain every millisecond.

**What.** The JAX AI stack and the compile path: JAX traces a jitted function →
StableHLO → **XLA** fuses ops and emits TPU machine code. JIT vs **AOT**
(`.lower().compile()`), the compilation cache, and reading a compiled program's
memory analysis to catch an **OOM before training starts**. Where **Flax NNX**
(model), **Optax** (optimizer) sit on top.

**How.** Sim: **fusion → HBM trips** — toggle op fusion on a small graph and watch
HBM round-trips collapse (ties directly to arithmetic intensity from 1.3). Lab:
companion **Colab notebook** (CPU-first, TPU-optional per our notebook standard) —
trace, lower, inspect the HLO, read `compiled.memory_analysis()`.

## Accuracy gates (verified 2026-06)

- **Flax NNX is the recommended API** for new code; **Linen is legacy-but-alive**
  (MaxText still uses it, no near-term deprecation). Teach NNX, name Linen as what
  you'll meet in production codebases. [flax.readthedocs.io/why]
- Compile path is **JAX → StableHLO → XLA** (not "JAX → HLO" hand-waving).
- AOT API: `jax.jit(f).lower(*args).compile()`; memory analysis available on the
  compiled object — verify exact method names against current docs at draft time.
- Compilation cache exists and matters for multi-host start time — verify current
  flag/API (`jax.config` / `JAX_COMPILATION_CACHE_DIR`) at draft time.

## Learning objectives

1. Draw the path: Python fn → trace (jit) → StableHLO → XLA fusion → TPU executable.
2. Explain what **fusion** buys in HBM-trip terms (link to arithmetic intensity).
3. Use **AOT lowering** to find compile-time facts (HLO, memory) *before* running.
4. Place Flax **NNX**, Optax, and the compilation cache in the stack.

## Must-learn spine

- Tracing: a jitted function runs once with abstract values; shapes are frozen
  (recompile on new shapes — the "why is my step slow" classic).
- Fusion: XLA merges elementwise chains into matmul epilogues → fewer HBM trips →
  higher arithmetic intensity (1.3 callback).
- JIT vs AOT: same compiler, different *when*; AOT = inspect/compile without
  devices-in-the-loop; catch OOM from `memory_analysis` before burning a slice.
- The stack ladder: JAX (numerics) · Flax NNX (modules) · Optax (optimizers) ·
  Orbax/Grain named as the next lesson's cast.

## Sim spec — `xla-fusion-explorer`

Small dataflow graph (matmul + bias + gelu + scale). Toggle **fusion off/on**:
unfused = each op a round-trip to HBM (count them, show bytes); fused = one kernel,
one trip. Readout: HBM trips, bytes moved, effective arithmetic intensity.
Checkpoint `observe-fusion` when fusion is first toggled on.
