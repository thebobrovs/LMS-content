## Scope boundary (the "no fluff" rule)
This is **not** a spec dump or a history-for-history's-sake topic. It is **"chasing
the bottleneck"**: each generation introduced a feature *specifically to fix what
broke the previous one at scale* (compute → memory → thermal → network → workload).
It bridges 1.1 ("what a TPU is") and 1.3 ("how the math works") by explaining **why**
the architecture evolved. Every generation in the lesson must be tied to *the
bottleneck it broke* — if a fact isn't a bottleneck story, cut it.

## Why / What / How
- **Why:** An engineer who sees the modern Pod (liquid-cooled, optically switched,
  split into 8t/8i) as arbitrary can't reason about it. Knowing *why* each feature
  exists turns trivia into a predictive mental model.
- **What:** The arc V1 → 8th gen, framed as a chain of bottlenecks and their fixes.
- **How:** Each generation hit a wall (power, memory, thermal, network, workload) and
  the next solved it — culminating in the training/inference split.

## Learning objectives
After this topic the learner can:
- Explain that TPU hardware evolves **strictly to eliminate the next operational bottleneck** (compute → memory → thermal → network → workload).
- Identify the **major architectural leaps** — when distributed-shared-memory Pods, **liquid cooling**, and **optical circuit switches** arrived — and *which bottleneck* each one broke.
- Explain **why the 8th gen split into 8t/8i**: training and serving have fundamentally different bottlenecks.

## Must-learn (the bottleneck chain)
1. **Early days (V1 → V2):** V1 was a pure **internal inference** accelerator. V2 moved to **training** by adding distributed shared memory — the first multi-chip **Pods**. *(bottleneck: single-chip → multi-chip training)*
2. **Thermal & network leaps (V3 → V4):** rising performance density broke air cooling → **liquid cooling (V3)**; Pods grew too big/failure-prone for static copper wiring → **optically reconfigurable / OCS (V4)** to route around dead chips. *(bottleneck: heat, then network reliability at scale)*
3. **Megascale era (v5p · Trillium/v6e · Ironwood/v7):** flexibility and raw scale climbed (Ironwood pushed Pod size to **~9,216 chips**). *(bottleneck: raw scale / pod size)*
4. **The workload split (8th gen):** training and serving bottlenecks diverged so far that the silicon **split into TPU 8t (training) and TPU 8i (inference)**. *(bottleneck: one chip can't optimize both — embeddings/throughput vs KV-cache/low-latency collectives)*

## Key terms (glossary additions — NEW)
- `liquid cooling` — introduced at **V3**; the fix when performance density broke air cooling.
- `ocs` (optical circuit switch) — introduced at **V4**; reconfigurable optical links that route around failed chips and reshape slices.
- `trillium` — the **v6e** generation (cost-efficient inference / smaller training).
- `ironwood` — the **v7 / TPU7x** generation; pushed Pod scale (~9,216 chips).
- *(`8t`/`8i`/`sparsecore`/`cae` already in the glossary from 1.1.)*
