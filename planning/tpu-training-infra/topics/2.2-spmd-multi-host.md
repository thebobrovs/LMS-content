## TLDR — why / what / how

**Why.** One host was easy (2.1). A multi-host slice runs the **same binary on every
host** (SPMD) — and the magic is that `jax.jit` + a *sharding* turns that one program
into a coordinated parallel computation, with the compiler (**Shardy**) inserting all the
cross-device communication. You never hand-write a `send`/`recv`. When it breaks, it
breaks at **rendezvous** — the L100 DCN/firewall trap becomes a debugging story here.

**What.** The SPMD contract (one binary × N hosts, per-device shards, compiler-inserted
collectives); the mesh + sharding API (`jax.make_mesh`, `PartitionSpec`, `NamedSharding`);
the three control modes (**Auto / Explicit / Manual `shard_map`**) with *automatic/declarative*
as the canonical first path; data-parallel batch sharding as the worked example; and
`jax.distributed.initialize()` + the coordinator/rendezvous. **Hard-knocks beat:** a host
missing at the barrier → timeout → it's a *networking* bug (DCN/firewall/IP), not a TPU bug.

**How.** Sim: **shard-and-collect explorer** — pick a mesh shape + a `PartitionSpec` for a
`[batch, features]` tensor and watch which chip owns which shard and which collective Shardy
inserts (all-reduce / all-gather), with a bytes-on-the-wire readout. Notebook: CPU-first with
**8 fake devices** (`XLA_FLAGS=--xla_force_host_platform_device_count=8`) — fully runnable; you
build a mesh, shard an array, `visualize_array_sharding`, and contrast auto vs `shard_map`.

## Accuracy gates (verified 2026-06; re-confirm fast-moving APIs at draft time)

- **Shardy is THE partitioner — and now the DEFAULT.** Default since **JAX 0.7.1**
  (`jax_use_shardy_partitioner = True`); GSPMD is the predecessor being removed (migration
  completing ~March 2026). Teach Shardy as current; name GSPMD only as history. Do **not**
  show the opt-out flag as a normal path. [docs.jax.dev/shardy_jax_migration, openxla.org/shardy]
- **Sharding modes (NEW since the original plan — get this right):** JAX now has three:
  - **Auto** — XLA/Shardy propagates sharding and inserts collectives; `jax.sharding.Mesh(...)`
    defaults to Auto. This is the "declarative, no hand-written comms" path → **the L200 canonical example.**
  - **Explicit** ("sharding-in-types") — a value's JAX type carries its sharding; `jax.make_mesh(...)`
    defaults to **Explicit**. Name it as "more control, sharding visible in the types."
  - **Manual** — `jax.shard_map` (now top-level, was `jax.experimental.shard_map`): you write
    per-device code and the collectives yourself. Name it as the escape hatch.
  Confirm `jax.make_mesh` signature + the per-mode defaults at draft time.
- **Mesh + sharding API:** `jax.make_mesh(axis_shapes, axis_names)` (modern) or
  `jax.sharding.Mesh(devices, axis_names)`; `jax.sharding.PartitionSpec` (elements: `None` =
  replicated, a mesh-axis name, or a tuple of axes); `jax.sharding.NamedSharding(mesh, spec)`;
  place data with `jax.device_put(x, NamedSharding(...))`. Confirm exact import paths.
- **`jax.distributed.initialize()`:** on **Cloud TPU call it with NO args** — coordinator
  address, `num_processes`, `process_id` are auto-detected. Off-TPU you pass
  `coordinator_address`/`num_processes`/`process_id`. Newer params worth a mention:
  `initialization_timeout`, `heartbeat_timeout_seconds` (fault tolerance), and
  `slice_index`/`partition_index` (Multislice). Rendezvous rides the **DCN**.
- **CPU device-faking for the notebook:** `XLA_FLAGS=--xla_force_host_platform_device_count=8`
  set **before** importing jax. Verify it still yields 8 `CpuDevice`s at draft time.
- **Collectives:** data-parallel gradients → **all-reduce**; gathering a sharded activation →
  **all-gather**; these ride **ICI** within a slice (1.4 torus callback), **DCN** across slices.

## Must-learn spine (with the SRE bridge baked into each beat)

1. **One program, N hosts (SPMD).** Every host runs the *same* `main.py`; JAX glues their
   local devices into one global **mesh**. *SRE bridge:* it's the same binary fanned out to
   every node — think a DaemonSet / one container image per host / MPI ranks, not a
   driver-and-workers split. You don't write the comms; you declare intent.
2. **Sharding is declarative.** You say *how* a tensor splits (`PartitionSpec` over named mesh
   axes); **Shardy** figures out *what communication* makes the math correct and inserts it.
   *SRE bridge:* like declaring a partition key and letting a query planner insert the
   shuffle — you describe the layout, the system generates the data movement.
3. **Data parallelism, the canonical case.** Shard the batch across a `data` axis, replicate
   params; the backward pass needs an **all-reduce** to sum gradients across shards. *SRE
   bridge:* all-reduce is the network shuffle; **bytes-on-the-wire = your cost**, and on a
   slice it rides **ICI** (1.4: why a long torus axis is the cheap place to put it).
4. **The control spectrum.** Auto (Shardy propagates) → Explicit (sharding in the types) →
   Manual (`shard_map`, you write the collectives). Start auto; reach for `shard_map` only
   when you need exact control. *SRE bridge:* managed → typed → hand-rolled, same as ORMs →
   typed query builders → raw SQL.
5. **Rendezvous is a networking step.** Before any ICI traffic, hosts find each other through
   a **coordinator** over the **DCN**. *SRE bridge:* it's gang-scheduling / leader-election /
   an etcd-style barrier — and the #1 failure is a node that can't reach the coordinator
   (firewall, wrong IP, MTU), which surfaces as a **barrier timeout**, not a chip error.

## Sim spec — `spmd-shard-explorer`

**Concept (one):** declaring a sharding determines shard ownership *and* the collective the
compiler must insert. **Standard:** Hyperstack tokens, light/dark + `data-theme`, deterministic
core, `prefers-reduced-motion` honored, real `createSim` SDK (classic `<script src="./sim-sdk.js">`),
one `sim.checkpoint("observe-spmd")`, `sim.resize` in rAF. No game/score framing. (Follow the
2.1 `xla-fusion-explorer` build for SDK wiring, theme, and reduced-motion patterns.)

**Layout.** A **2×4 mesh** of chips grouped into **2 hosts** (host boundary drawn explicitly —
reinforces "cross-host = DCN"). A `[batch, features]` tensor. The learner picks a `PartitionSpec`:
- `('data', None)` → batch sharded across the `data` axis, features replicated (data parallel).
- `(None, 'model')` → features sharded (tensor/model parallel).
- `PartitionSpec()` (fully replicated) → every chip holds the whole tensor.

**What it shows.** (a) Shard ownership painted per chip (which slice of the tensor each holds);
(b) the **collective Shardy inserts** for a sample op under that spec (all-reduce / all-gather /
none), with arrows on ICI links (intra-host) vs the host boundary (DCN) when relevant; (c) a
**bytes-on-the-wire** readout so the cost is concrete; (d) a one-line note translating the choice
("data-parallel: replicate params, all-reduce grads"). Deterministic numbers from tensor dims ×
dtype — no `Math.random` in visuals. Checkpoint fires on the first spec change.

**Audience check.** Run the audience-reviewer on the sim's labels/notes — Sam must be able to say,
without ML background, what each spec costs on the wire and which network carries it.

## Glossary needs (`glossary/tpu-training-infra.json`)

Already present (reuse): `ici`, `dcn`, `multislice`, `tpu vm`, `xla`. **Add:**
- `spmd` — single program, multiple data: one identical binary per host/device, each on its own shard.
- `mesh` — a named N-D grid of devices you map shardings onto (axes like `data`, `model`).
- `sharding` / `PartitionSpec` — the declaration of how a tensor's dims split across mesh axes.
- `collective` — a multi-device communication op (all-reduce, all-gather, reduce-scatter) the
  compiler inserts; the bytes it moves are the parallelism cost.
- `all-reduce` — sum (or combine) a value across all shards and hand everyone the result; the
  data-parallel gradient step.
- `shardy` — JAX's MLIR-based partitioner (default since 0.7.1), successor to GSPMD; inserts collectives.
- `coordinator` / `rendezvous` — process 0's barrier where hosts find each other over DCN at startup.
- `shard_map` — the manual escape hatch: per-device code where you write the collectives yourself.
Each definition must pass the SRE lens (anchor to an infra concept; state the systems impact).
