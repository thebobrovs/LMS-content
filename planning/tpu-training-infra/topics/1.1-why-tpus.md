# 1.1 Why TPUs? Cloud TPUs & the TPU VM  ("the box")

## Scope boundary (1.1 vs 1.2)
1.1 is **"the box"**: what a TPU is, how you *reach* it (the VM), and the *anatomy*
of the chip. 1.1 must **not** teach how the systolic array computes or arithmetic
intensity — that is 1.2 ("the silicon"). 1.1 names the MXU and forward-refs it.

## Why / What / How
- **Why:** An infra engineer's first wrong mental model is "a TPU is a network card
  I call." It isn't — you **SSH into a host CPU that sits in front of the
  accelerator**. The VM model + the physical anatomy are the foundation every later
  topic (provisioning, data feeding, debugging) stands on.
- **What:** A TPU is an ML **ASIC**; its chip = TensorCore(s) (MXU + vector + scalar,
  with SMEM/VMEM) + HBM + SparseCores, wired to neighbours by ICI; you reach it
  through a host VM; capability ladders chip → host → slice → Pod → Multislice.
- **How:** You run on the host; it dispatches to the chip over PCIe. Explore the
  chip's parts in the anatomy sim.

## Learning objectives
After this topic the learner can:
- Explain **what a TPU is** (an ML ASIC) and why purpose-built hardware exists.
- Describe the **TPU VM model**: SSH into a host attached to the chips; code runs on the host, dispatches to the TPU — no per-op network hop.
- Identify the **parts of a TPU chip** (TensorCore = MXU + VPU + scalar; SMEM/VMEM; SparseCore; HBM) and what each does.
- Lay out the **scale ladder** (chip → host → slice → Pod → Multislice) and pick a **generation** (v5e/v6e inference, v5p training).

## Must-learn (keep nothing else but this)
1. A TPU is an ML **ASIC you reach through a host VM** — not a network-attached card; you run on the host. *(sets up 1.4 provisioning)*
2. The chip = **TensorCores (MXU + vector + scalar, with SMEM/VMEM) + HBM + SparseCores**, wired to neighbours by **ICI**. *(sets up 1.2 silicon, 1.3 topology)*
3. Capability **ladders** chip→host→slice→Pod→Multislice; **generation** choice ≈ training (v5p) vs inference (v5e/v6e).
