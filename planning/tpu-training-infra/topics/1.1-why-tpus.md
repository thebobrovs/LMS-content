# 1.1 Why TPUs? Cloud TPUs & the TPU VM  ("the box")

**Topic id:** `ml-systems/why-tpus` · **Level:** 100 · **Difficulty:** beginner · **Est:** 11 min
**Status:** built (on staging) — **plan back-filled; the built topic has a generation gap (no 8t/8i) that MUST be fixed before promotion to production**

## Scope boundary (1.1 vs 1.2)
1.1 is **"the box"**: what a TPU is, how you *reach* it (the VM), and the *anatomy*
of the chip. 1.1 must **not** teach how the systolic array computes or arithmetic
intensity — that is 1.2 ("the silicon"). 1.1 names the MXU and forward-refs it.

## Why / What / How
- **Why:** An infra engineer's first wrong mental model is "a TPU is a network card
  I call." It isn't — you **SSH into a host CPU that sits in front of the
  accelerator**. The VM model + the physical anatomy are the foundation every later
  topic (provisioning, data feeding, debugging) stands on.
- **What:** A TPU is an ML **ASIC**; its chip = TensorCore(s) (MXU + vector + scalar,
  with SMEM/VMEM) + HBM, wired to neighbours by ICI. Its **specialized blocks now
  diverge by workload**: **TPU 8t** (training) keeps **SparseCores** (+ an LLM Decoder
  Engine); **TPU 8i** (inference) replaces them with a **Collectives Acceleration
  Engine (CAE)** and 3× the on-chip SRAM (384 MB VMEM) to hold the KV cache. You reach
  it through a host VM; capability ladders chip → host → slice → Pod → Multislice.
- **How:** You run on the host; it dispatches to the chip over PCIe. Explore the
  chip's parts in the anatomy sim.

## Learning objectives
After this topic the learner can:
- Explain **what a TPU is** (an ML ASIC) and why purpose-built hardware exists.
- Describe the **TPU VM model**: SSH into a host attached to the chips; code runs on the host, dispatches to the TPU — no per-op network hop.
- Identify the **parts of a TPU chip** (TensorCore = MXU + VPU + scalar; SMEM/VMEM; SparseCore; HBM) and what each does.
- Lay out the **scale ladder** (chip → host → slice → Pod → Multislice) and pick a **generation** (v5e/v6e inference, v5p training).

## Must-learn (keep nothing else but this)
1. A TPU is an ML **ASIC you reach through a host VM** — not a network-attached card; you run on the host. *(sets up 1.4 provisioning)*
2. The chip = **TensorCores (MXU + vector + scalar, with SMEM/VMEM) + HBM**, wired to neighbours by **ICI** — and its **specialized blocks differ by workload**: **8t (training) → SparseCores**; **8i (inference) → a CAE + 3× SRAM**. *(sets up 1.2 silicon, 1.3 topology, 3.1 collectives)*
3. The **8th gen splits the chip itself**: **TPU 8t** for training (SparseCore, 3D torus) vs **TPU 8i** for inference (CAE, Boardfly) — the clearest proof that "the box" is tailored to the workload. (Lineage: v5e/v6e inference, v5p/Ironwood training.)

## Key terms (glossary)
- `tpu`/`asic`, `tensorcore`, `mxu`, `vpu`, `hbm`, `sparsecore`, `tpu vm`, `ici`, `multislice` — *(all exist in the path glossary)*.
- **`cae`** (Collectives Acceleration Engine) — **NEW**: the TPU 8i block that replaces the four SparseCores; aggregates across cores with near-zero latency, cutting on-chip collective latency ~5×. Add next to `sparsecore`.
- **`tpu 8t` / `tpu 8i`** — **NEW**: 8th-gen training vs inference chips (SparseCore+3D-torus vs CAE+Boardfly).
