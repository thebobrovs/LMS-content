## TLDR — why / what / how
**Why.** The track dives into precision and shapes assuming "tensor" is understood. To the hardware,
a tensor is just a **multidimensional array of numbers mapped to 1-D memory** — and if an operator
can't see how adding a dimension (rank) *explodes* the footprint, they can't reason about HBM. We
define it, the most foundational L100 beat.
**What.** Borrow Dan Fleisch's pedagogy (arrow → shadows/projections → array; rank → blocks 1/3/9/27)
but land on the **operator payoff**, not physics. **Array-first:** in ML a tensor is *just an n-d
array*; basis vectors/invariance are the lovely *origin of the word*, carried by Fleisch's video, not
machinery the operator uses.
**How.** Two sims + Fleisch's video. `vector-basis-explorer` (Sim 1): an isometric arrow casting
shadow-projections onto the axes → the `[x,y,z]` array (geometry becomes the stored array).
`tensor-rank-explorer` (Sim 2): rank 0→3 blocks scaling 1→3→9→27, climaxing in the **HBM footprint**.

## Accuracy gates (verified; re-confirm at draft)
- **ML tensor = n-d array.** It has no basis vectors / transformation rules at runtime — that's the
  *physics* tensor (Fleisch's climax). Teach array-first; mark the geometry as origin-of-the-word.
- **Rank = number of indices / dimensions** (a.k.a. ndim, order). **Disambiguate from linear-algebra
  matrix rank** (independent rows) — different thing; say so in one line.
- **Rank ↔ counts (N=3):** scalar rank 0 = 1, vector rank 1 = 3, matrix rank 2 = 9, rank 3 = 27.
  Footprint = product of dims × dtype bytes; grows multiplicatively with each new dimension.
- **Basis vector / projection:** keep light — î ĵ k̂ are length-1 unit rulers; a component is the
  length of the arrow's shadow on an axis. (Don't teach coordinate invariance.)
- **Video:** Dan Fleisch, "What's a Tensor?", id `f5liqUk0ZTw` (confirmed) — embed via `<YouTube>`.
- **1-D memory:** an n-d tensor is stored flattened (row-major) in linear HBM — the serialization bridge.

## Learning objectives
1. Translate "tensor" → "multidimensional array."
2. Explain how a geometric arrow becomes a stored array (components = shadows/projections).
3. Define **rank** = number of indices to locate one value (≠ matrix rank).
4. Compute a tensor's footprint from rank+dims, and see why each added dimension multiplies it.

## Must-learn spine (SRE bridge per beat)
1. **A tensor is an n-d array.** *SRE bridge:* rank 0 = a single config value (`MTU=8896`); rank 1 = a
   1-D log of temps; rank 2 = a routing table; rank 3 = routing tables across VRFs.
2. **Geometry → array (shadows).** An arrow's projections onto the axes are its components `[x,y,z]`.
   *SRE bridge:* unit/basis vectors are the agreed ruler — like sender+receiver agreeing on the
   protocol so the integers mean something.
3. **Stored in 1-D memory.** The n-d array is flattened (row-major) into linear HBM. *SRE bridge:*
   serializing a nested object into a flat byte string; strides are the offsets.
4. **Rank → exponential footprint.** Adding a dimension multiplies the whole structure (1→3→9→27).
   *SRE bridge:* this is why LLM tensors eat 95 GB of HBM so fast — it's the climax, not invariance.
